## Problem

Before the first release, nobody has checked as a whole that every rule in the security checklist holds, that dependencies have no known vulnerabilities, or that the accepted risks are still acceptable. The review is the author's own (D51).

## Solution

Automated checks run first: `pnpm audit`, ESLint with its security plugin, and Electron's own security warnings in the developer console. Then the user goes through every row of the security checklist, marking each one done with the commit that covers it or listing it under the accepted risks, and re-reads every accepted risk.

## User Stories

1. As the developer, I want `pnpm audit`, the ESLint security rules and Electron's security warnings run and their findings fixed or explained.
2. As the developer, I want every checklist row marked done with the commit that covers it, or listed as an accepted risk.
3. As the user, I want to re-read every accepted risk and confirm each is still acceptable, knowing the app is for a small group of friends.

## Steps

### Step 01 — Automated checks

**Status:** Implementing
**Execution type:** AFK
**Stories covered:** US-1

#### What To Build

`pnpm audit`, ESLint with its security plugin, and the packaged app with its developer console are run. Electron's security warnings are read from the console. Each finding is fixed, or explained in the security checklist with why it does not apply.

#### Affected repositories and layers

- newcord: wherever a finding is fixed; `docs/guide/13-security-checklist.md` for explanations

#### Acceptance Criteria

- [ ] `pnpm audit` reports no unexplained high or critical findings
- [ ] `pnpm lint` passes with the security plugin and no disabled security rules without a written reason
- [ ] Electron prints no security warnings in the development console, or each is explained
- [ ] `pnpm test` and `pnpm typecheck` pass

### Step 02 — Checklist and accepted risks

**Status:** Implementing
**Execution type:** HITL
**Stories covered:** US-2, US-3

#### What To Build

A "Done in" column is added to `13-security-checklist.md`. The agent proposes the commit that covers each row. The user reviews each row and marks it done, or moves it to the accepted risks with a reason. The user then re-reads every accepted risk and confirms it, with the agent noting any that changed since it was accepted (for example after D73).

#### Affected repositories and layers

- newcord: `docs/guide/13-security-checklist.md`

#### Acceptance Criteria

- [ ] Every row of the checklist has a commit in "Done in" or a line in the accepted risks
- [ ] The user has confirmed every accepted risk, and any that no longer apply are removed with a note
