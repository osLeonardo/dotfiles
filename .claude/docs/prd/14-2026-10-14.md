## Problem

The server and relay only run on the developer's PC. Friends on other networks cannot sign in, and release builds point at hostnames that do not exist yet.

## Solution

One Oracle Cloud Always Free Arm machine (D52) runs:
- the backend as a systemd service
- its SQLite database
- coturn

nginx shares port 443 by hostname between the backend and the relay (D53). Two DuckDNS names point at the machine (D54), with Let's Encrypt certificates renewed automatically. A nightly backup goes to a private Object Storage bucket for 7 days. The strict-firewall test moved here from M3 (#8) is part of the done-when.

## User Stories

1. As a friend, I want to sign in from any network through the backend's name.
2. As a friend behind a strict firewall, I want Calls to connect through the relay on port 443.
3. As the operator, I want certificates renewed automatically.
4. As the operator, I want the backend to see real client addresses (for rate limits), not 127.0.0.1.
5. As the operator, I want a nightly backup kept for 7 days that restores on a fresh machine.
6. As the operator, I want the backend and coturn to run as non-root users with only what they need.
7. As the developer, I want every configuration file for the machine kept in the repository without secrets, so that the setup is repeatable.

## Implementation Decisions

### Interfaces and Contracts

- The hostnames are `<name>.duckdns.org` (backend) and `<name>-turn.duckdns.org` (relay), from #12. Release builds use these addresses (D65).
- Fastify uses `trustProxy: "127.0.0.1"` and listens only on 127.0.0.1. nginx passes the client address with the PROXY protocol (`14-server-deployment.md` step 5).

**Filled in during this spec (not stated in the guide) — confirm at Gate 1:**

1. **A `deploy/` folder in the repository** holds the nginx configuration, coturn's production configuration, the systemd unit and the backup script as templates with no secrets.
2. **The server is deployed by pulling the repository on the machine and building there,** as the guide's step 8 implies. There's no deployment automation in v1.

### Architectural Decisions (ADR)

This repository records decisions in `docs/guide/03-decisions.md`, not ADRs.

- D52 Oracle Cloud Always Free, converted to pay-as-you-go; D53 port 443 shared by name; D54 DuckDNS.
- Settings in `14-server-deployment.md`: Arm, 1 core and 6 GB, Ubuntu 24.04; two hostnames; certbot over HTTP on port 80; UDP 49152–49407; nightly backups kept 7 days.

**Status:** Implementing
**Execution type:** AFK

#### What To Build
