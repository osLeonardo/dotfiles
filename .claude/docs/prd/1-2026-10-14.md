# 1 - Repository scaffold (newcord)

**Date:** 2026-10-14
**Branch type:** Feature
**Status:** Draft

**Repository:** newcord · **Issue:** [osLeonardo/newcord#1](https://github.com/osLeonardo/newcord/issues/1) · **Milestone:** M1 · Backend and accounts · **Branch:** `feature/1-repository-scaffold`

## Problem

The newcord repository holds only the design (`docs/guide/`), the glossary and the agent instructions. There is no workspace, no runnable desktop app, no server and no shared package, so none of M1's feature work (issues #2 and #3) can start. There is also no CI before M5 (D68), so every quality check has to be runnable locally with one command from day one, or it will not be run at all.

## Solution

A pnpm 11 monorepo, pinned to Node.js 26, with three packages — `apps/desktop` (Electron + React from the electron-vite template), `apps/server` (Fastify with a `GET /health` route) and `packages/shared` (`@newcord/shared`, consumed by both apps) — plus root commands for tests, lint, format and typecheck that cover every package. Running the desktop app opens its window; running the server answers `{"ok":true}` on `http://localhost:3000/health`. The repository is licensed AGPL-3.0-or-later and ignores secrets, databases and build output.

## User Stories

1. As the developer, I want to start the desktop app in development mode with one command (`pnpm --filter desktop dev`), so that I can see the window and iterate on the interface.
2. As the developer, I want to start the server in watch mode with one command (`pnpm --filter server dev`), so that it restarts as I change it.
3. As the developer, I want `GET http://localhost:3000/health` to answer `{"ok":true}`, so that I can tell the server is up.
4. As the developer, I want `@newcord/shared` importable from both the desktop app and the server, so that schemas and types written in #2 are defined once.
5. As the developer, I want the desktop app to bundle `@newcord/shared` into its build, so that the shared TypeScript source works without being published or prebuilt.
6. As the developer, I want one root command each for tests, lint, format and typecheck that cover every package, so that I can check a change before merging without CI (D68).
7. As the developer, I want the repository to require Node.js 26 and pnpm 11.5.2, so that my machine, later CI and the production server run the same toolchain.
8. As the developer, I want pnpm to refuse any dependency install script I have not approved by name, so that nothing unreviewed runs on my machine.
9. As the developer, I want the hoisted dependency layout set where pnpm 11 actually reads it, so that electron-builder can package the app in M5.
10. As the developer, I want the AGPL-3.0 text in `LICENSE` and `AGPL-3.0-or-later` in every `package.json` (D63), so that the license is unambiguous from the first commit.
11. As the developer, I want environment files, local databases and build output ignored by git, so that secrets and generated files are never committed to this public repository.
12. As the developer, I want line endings normalised in the repository, so that checkouts on different machines and tools do not produce whole-file diffs.
13. As a future agent, I want the Commands section of `CLAUDE.md` to list the real commands, so that I can run and check the project without guessing.
14. As a future agent, I want the working title "newcord" used wherever the guide says `your-app`, so that D58's rename before M5 is one search-and-replace.

## Implementation Decisions

### Interfaces and Contracts

- `GET /health` → `200` with body `{"ok":true}`, on port 3000.
- Package names: `desktop`, `server`, `@newcord/shared` (the first two match the `--filter` commands in `CLAUDE.md`).
- Root scripts: `test`, `lint`, `format`, `typecheck`, each covering all three packages.

### Architectural Decisions (ADR)

This repository records decisions in `docs/guide/03-decisions.md`, not ADRs.

- D26 one repository; D27 electron-vite with electron-builder; D28 Fastify with `@fastify/websocket`; D31 pnpm; D32 Vitest; D33 ESLint with Prettier; D58 working title "newcord"; D63 AGPL-3.0-or-later; D65 server address built in (the address itself is wired in #3); D68 no CI before M5.
- Settings in `07-m1-setup.md`: Node.js 26 (`engines.node` and `.node-version`); pnpm 11.5.2 (`packageManager`), with every pnpm setting in `pnpm-workspace.yaml` — `nodeLinker: hoisted` and the `allowBuilds` approvals.
- Install scripts approved by name: `electron` and `esbuild`, plus any other package the template's install lists only after asking the user.
- One ESLint, one Prettier and one Vitest configuration at the root; package-level copies that come with the template are folded into them.
- electron-builder's `appId` is `com.newcord.desktop`, replaced with the final name before M5 (D58).

### Schema Changes

None. Tables arrive with #2.

## Out of Scope

- Accounts, tokens, the key directory, the WebSocket hub and the server database (#2).
- Desktop hardening: the template's `sandbox: false` and its preload exposing `@electron-toolkit/preload`'s `electronAPI` (which includes `ipcRenderer`) stay as generated until #3 replaces them; the strict CSP, IPC checks, navigation blocking and the built-in server address (D65) are #3.
- The device identity key, local database and screens (#3).
- CI workflows of any kind (D68) and release packaging beyond the `appId` (M5).

## Additional Notes

- Node.js 26.8.1 and pnpm 11.5.2 are installed on the developer's Windows machine.
- The guide was corrected on 2026-10-14 for pnpm 11 (settings no longer read from `.npmrc`; `allowBuilds` replaced `onlyBuiltDependencies`; `strictDepBuilds` on by default). Those edits were merged into `main` in PR #16 before this issue started.
- `07-m1-setup.md` is the step-by-step source; this PRD adds the pnpm 11 corrections, the root `typecheck` script and the `.gitignore` / `.gitattributes` the issue asks for.
- Risk: `pnpm create @quick-start/electron` may still ask interactive questions even with a template given.
- Risk: library behavior differing from the guide must be reported to the user with options, never silently worked around (`CLAUDE.md`).

## Steps

### Step 01 — Workspace root, shared package and server health check

**Status:** Implementing
**Execution type:** AFK
**Stories covered:** US-2, US-3, US-4, US-7, US-8, US-9, US-10, US-11, US-12, US-14

#### What To Build

A pnpm workspace at the repository root with the server and the shared package, ending with `pnpm --filter server dev` serving `{"ok":true}` on `http://localhost:3000/health`. The server imports at least one export from `@newcord/shared`, proving the workspace link. The root pins Node.js 26 and pnpm 11.5.2, keeps every pnpm setting in `pnpm-workspace.yaml`, carries the license, and ignores secrets, databases and build output.

Included: `07-m1-setup.md` steps 1–4, 6–8 (server side of the link), 9 (for the packages present) and 11, plus `.gitignore` and `.gitattributes`. The pnpm-11 corrections to the guide were already merged in PR #16. Not included: the desktop app (Step 03), test/lint/format/typecheck tooling (Step 02), any schema or protocol content in the shared package (#2).

#### Affected repositories and layers

- newcord: repository root (workspace and tooling configuration, license, git attributes), `apps/server` (entry point and health route), `packages/shared` (package skeleton)

#### Acceptance Criteria

- [ ] `pnpm-workspace.yaml` lists `apps/*` and `packages/*` and sets `nodeLinker: hoisted`; there is no `.npmrc` holding pnpm settings
- [ ] The root `package.json` is private, has `"packageManager": "pnpm@11.5.2"`, `engines.node` requiring major version 26, and `"license": "AGPL-3.0-or-later"`; `.node-version` contains `26`
- [ ] `LICENSE` contains the unmodified GNU AGPL version 3 text, and every `package.json` has `"license": "AGPL-3.0-or-later"`
- [ ] `apps/server/package.json` has `"type": "module"`, the name `server`, and a `dev` script running `tsx watch src/index.ts`; `fastify` and `@fastify/websocket` are dependencies
- [ ] `packages/shared/package.json` is named `@newcord/shared` and is a workspace dependency of `server`
- [ ] `pnpm install` completes with no pending build approvals, and `pnpm-workspace.yaml` `allowBuilds` lists only packages approved by name (`esbuild`, and nothing the user was not asked about)
- [ ] With `pnpm --filter server dev` running, `GET http://localhost:3000/health` returns status 200 and the body `{"ok":true}`
- [ ] `.gitignore` excludes at least `node_modules`, build output (`out`, `dist`), `coverage`, `.env` files and SQLite database files
- [ ] `.gitattributes` normalises text line endings to LF, and `git add --renormalize .` leaves no further changes

#### Blockers

#### Implementation Notes

- pnpm 11 reads no non-auth settings from `.npmrc` and stops the install while any install script is neither approved nor denied. `tsx` pulls in `esbuild`, which has an install script; `esbuild` is pre-approved by the guide (`pnpm approve-builds esbuild`). If any other package asks, stop and ask the user — do not approve or deny it yourself.
- The root `package.json` should also be `"type": "module"`, since Step 02 adds `eslint.config.js` in ESM form.
- Keep the server's app construction separate from `listen()` so Step 02 can test the health route through Fastify's request injection without opening a port. The server's TypeScript settings must allow top-level `await` (NodeNext modules, ES2022 or later).
- `@newcord/shared` ships TypeScript source (its entry points at `src`); `tsx` runs it directly in the server. Keep its exports to a minimal placeholder — schemas, protocol versions and other values belong to #2.
- Get the license text from https://www.gnu.org/licenses/agpl-3.0.txt.
- Wherever the guide says `your-app`, use `newcord` (D58).

### Step 03 — Desktop app joins the workspace

**Status:** Implementing
**Execution type:** HITL
**Stories covered:** US-1, US-4, US-5, US-8, US-14

#### What To Build

The desktop app, generated from electron-vite's React and TypeScript template as package `desktop`, running with `pnpm --filter desktop dev` and opening its window. It imports `@newcord/shared` and bundles it into its build rather than treating it as an external dependency. It joins the root test, lint, format and typecheck scripts, which all still pass. electron-builder's `appId` is `com.newcord.desktop`.

Included: `07-m1-setup.md` steps 5, 8 (desktop side) and 9 (desktop install scripts), folding the template's own tooling configuration into the root, step 12's check. Not included: any change to the template's window settings, preload or CSP (#3), packaging or update configuration beyond the `appId` and product name (M5).

#### Affected repositories and layers

- newcord: `apps/desktop` (generated app: main process, preload, renderer, electron-vite and electron-builder configuration), repository root (tooling configuration and scripts extended to cover the desktop app, build approvals in `pnpm-workspace.yaml`)

#### Acceptance Criteria

- [ ] `apps/desktop` exists, generated from the `react-ts` template, with the package name `desktop` and `"license": "AGPL-3.0-or-later"`
- [ ] electron-builder's configuration has `appId` `com.newcord.desktop` and product name `newcord`
- [ ] `@newcord/shared` is a workspace dependency of `desktop`, at least one export is used from the main process and one from the renderer, and the main-process build output contains the shared code rather than importing the package at run time
- [ ] `allowBuilds` in `pnpm-workspace.yaml` lists only packages approved by name: `electron`, `esbuild`, and any other the user explicitly approved
- [ ] The template's own ESLint, Prettier and `.npmrc` files are removed or folded into the root, and the root `test`, `lint`, `format` and `typecheck` scripts cover `apps/desktop` and pass
- [ ] The template's window settings, preload and CSP are unchanged from what it generated
- [ ] The user confirms that `pnpm --filter desktop dev` opens the window
- [ ] With the desktop app and the server running at the same time, `http://localhost:3000/health` still returns `{"ok":true}`

#### Blockers

- [Step 02 — Tests, lint, format and typecheck across the workspace](#step-02--tests-lint-format-and-typecheck-across-the-workspace)

#### Implementation Notes

- Run the generator from `apps/`: `pnpm create @quick-start/electron desktop --template react-ts`. It may still ask questions; decline the updater plugin (automatic updates are M5, D29) and the download mirror. Relay any other question to the user.
- electron-vite externalizes dependencies for the main and preload builds by default. Exclude `@newcord/shared` from that so it is bundled; the option's name differs between electron-vite versions, so check the installed version's documentation.
- The template ships a `.npmrc`. pnpm 11 ignores non-auth settings there; delete it, and if it held something the build needs, ask the user before adding the equivalent to `pnpm-workspace.yaml`.
- `electron` downloads its binary in an install script and must be approved by name. Any package other than `electron` and `esbuild` asking to run an install script needs the user's approval first (`CLAUDE.md`).
- The template's `sandbox: false` and its preload exposing `electronAPI` from `@electron-toolkit/preload` break rules in `CLAUDE.md`, but fixing them is #3. Leave them as generated.
- If ESLint's security or React hooks rules flag generated template code, report it and ask how to handle it. Do not disable the rules or silence them inline.
