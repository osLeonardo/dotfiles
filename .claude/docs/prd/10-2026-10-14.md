## Problem

The app works, but it does not yet behave like a background chat app on Windows. It has no tray icon, does not start with Windows, shows no notifications for new messages, and its settings are scattered: the Call settings panel from M3 (#9) is temporary. Several decided behaviours are still missing:
- close to tray (D15b)
- start at login (D46)
- notification previews hidden while sharing (D15)
- one place for every setting

## Solution

- **Tray:** a tray icon with Open, Mute or Unmute, and Quit. Closing the window hides it to the tray unless "quit on close" is set (D15b). The first close shows a one-time notification that the app is still running. Launching the app again shows the window (the single-instance lock from #9).
- **Start at login:** on by default from the first run, opening hidden in the tray. The first screen says so and where to turn it off (D46).
- **Notifications:** sent from the main process, one per Group, updated as messages arrive, with no notification for the chat that is open and focused. Previews are full by default, or sender-only or generic as set (D15), and always generic while a screen share is running. Clicking one opens that Group. The Group list shows unread counts.
- **Settings screen:** four sections, Audio, Video, Privacy and App, replacing M3's temporary panel. Settings are stored per Device and survive restarts.

## User Stories

1. As a user, I want closing the window to keep the app running in the tray, so that I still get messages and stay in Calls.
2. As a user who prefers it, I want a setting that makes closing the window quit the app (D15b).
3. As a user closing the window for the first time, I want to be told the app is still running and how to bring it back.
4. As a user, I want a tray menu to open the app, mute or unmute, and quit.
5. As a user, I want the app to start with Windows, hidden in the tray, and to be told on first run where to turn that off (D46).
6. As a user, I want a notification when a message arrives in a Group I am not looking at, one per Group, updated rather than piling up.
7. As a user, I want to choose full previews, sender only or a generic notification (D15).
8. As a user sharing my screen, I want notifications always generic, so that viewers never see my messages (D15).
9. As a user, I want clicking a notification to open that Group.
10. As a user, I want unread counts on the Group list, so that I can see where new messages are.
11. As a user, I want one settings screen with Audio (microphone mode, push-to-talk key, mute hotkey, input device, voice-activity sensitivity), Video (codec), Privacy (Hide my IP, previews) and App (start at login, close behaviour).
12. As a user, I want my settings kept on this computer across restarts.

## Implementation Decisions

### Interfaces and Contracts

- Notifications come from the main process. Windows requires `app.setAppUserModelId` with the same ID as electron-builder's `appId`.
- Settings are stored in the app's local database, per Device. M3's Call settings move into the Audio, Video and Privacy sections unchanged.

**Filled in during this spec (not stated in the guide) — confirm at Gate 1:**

1. **Unread counts** per Group in the Group list, cleared when the Group is opened. #6 deferred them to M4, and the guide's M4 steps do not list them.
2. **Voice-activity sensitivity** is a slider over the threshold Step 03 of #9 uses, with the M3 default in the middle.

### Architectural Decisions (ADR)

This repository records decisions in `docs/guide/03-decisions.md`, not ADRs.

- D15 notification previews; D15b close behaviour; D46 start at login; D47's one-time notice (still useful on Windows); D73 Windows only.
- Settings in `11-m4-build.md`: mute hotkey `Ctrl+Shift+M`; no push-to-talk key until chosen; one notification per Group, none for the open and focused chat; settings stored per Device.

### Schema Changes

The app's local database gains unread counts per Group and the remaining settings: preview mode, start at login, close behaviour, input device and sensitivity.

### Step 02 — Notifications and unread counts

**Status:** Implementing
**Execution type:** HITL
**Stories covered:** US-6, US-7, US-8, US-9, US-10

#### What To Build

The main process shows a notification when a Chat message arrives in a Group that is not open and focused: one per Group, replaced as further messages arrive. ### Step 03 — Settings screen

**Status:** Implementing
**Execution type:** AFK
