# 12 - Choose the final name and replace the working title (newcord)

## Problem

The app has been built as "newcord", a working title (D58) that echoes another company's trademark. Before anything ships, the name must be final. electron-builder's `appId` sets the Windows install identity and the update channel, so changing it after a release would orphan every install. The DuckDNS names and certificates are first set up in deployment (#14).

## Solution

The user chooses the final name. It is then replaced everywhere "newcord" appears:
- package names, the `appId`, the product name, window titles and interface text
- the docs and the planned DuckDNS hostnames
- the GitHub repository, the local folder and the workspace Repository Map entry

## User Stories

1. As the user, I want to choose the app's final name from a few options with their pros and cons, recorded as a decision.
2. As a friend installing the app, I want the installer, the window and the tray to show the real name.
3. As the developer, I want no trace of "newcord" left except in the decision log's history, so that the rename is complete before the first release.
4. As the developer, I want the GitHub repository and local folder renamed, with GitHub's redirect keeping old links working.

## Implementation Decisions

### Interfaces and Contracts

- New identifiers derived from the chosen name:
  - `@<name>/shared` and `@<name>/mls`
  - `com.<name>.desktop`
  - the product name
  - `<name>.duckdns.org` and `<name>-turn.duckdns.org`

### Architectural Decisions (ADR)

This repository records decisions in `docs/guide/03-decisions.md`, not ADRs.

- D58: build with the working title, choose the final name before M5 starts. The choice itself becomes the next D-entry.

### Schema Changes

None. The local database file name may change with the product name; if it does, the app must find the old file.

## Out of Scope

- Logo and icon design (the template's icons stay unless the user supplies new ones).

## Additional Notes

- Must be done before #13 and #14.
- The workspace Repository Map lives in `{root}/.claude/CLAUDE.md`; changing it needs the user's go-ahead at that moment.
- DuckDNS names are first-come, first-served; check that the chosen name's hostnames are free before deciding.

### Step 02 — Replace the working title everywhere

**Status:** Implementing
**Execution type:** AFK
**Stories covered:** US-2, US-3, US-4

#### What To Build

"newcord" is replaced by the chosen name in package names, `appId`, product name, window titles, interface text, docs and planned hostnames. With the user's go-ahead at that moment, the GitHub repository and the local folder are renamed and the workspace Repository Map entry is updated. If the local database's file name changes, the app still finds an existing database.

#### Affected repositories and layers

- newcord: every package, `docs/`, `CLAUDE.md`, `CONTEXT.md`
- Workspace: `{root}/.claude/CLAUDE.md` (Repository Map, with the user's go-ahead)
- GitHub: repository name

#### Acceptance Criteria

- [ ] A case-insensitive search for "newcord" finds it only in the decision log's history
- [ ] `pnpm install`, `pnpm test`, `pnpm lint` and `pnpm typecheck` pass after the rename
- [ ] The app starts with the new name and finds a database created under the old name
- [ ] The GitHub repository and local folder are renamed, the git remote points at the new URL, and the Repository Map entry is updated
