## Development environment structure

> **The `{root}` symbol:** throughout this project's documentation, `{root}` represents the **parent directory of `.claude/`** — that is, the directory the agent was started from.
> This path varies per machine and must never be replaced with a hardcoded absolute path.

The agent must always be started from `{root}`, which is the working root.
Each subfolder inside `{root}` is an independent Git repository.

- A repository's name does not always reflect every domain it contains. Check the Repository Map below before deciding where to act.
- Each repository should have its own `CLAUDE.md` with specific technical details, internal structure and local conventions.
- This file (the global `CLAUDE.md`) serves exclusively as a high-level orientation map. Technical details and code conventions live in specific `.md` files and must be read on demand only.

## The `.claude` directory

The `{root}/.claude` directory is the support space for the agent's work, organized as follows:

- **`.claude/skills/`** — custom skills that extend the agent's capabilities. Only custom skills belong here.
- **`.claude/docs/`** — centralizes all documentation and artifacts produced by the agent:
  - **`handoffs/`** — documents that compact the context of a closed session so a new agent can continue the work.
  - **`knowledge/`** — global rules and shared patterns about the workspace and all its repositories. Documents in this folder must be loaded into memory only when you need them or the user asks. In `.md` files, always look for `Quick references` sections — they hold the rules for loading other files.
  - **`issues/`** — raw issue notes, copied from GitHub or written by hand.
  - **`prd/`** — documents specifying requirements, scope and acceptance criteria for a feature before implementation.
  - **`scripts/`** — helper executable scripts for project setup.
  - **`tasks/`** — issue closeout documents generated by `document-task` at the end of an implementation (ready to paste as an issue comment or PR body).
  - **`templates/`** — templates for documentation used by the agent and in skills.

**Important:**
- Never create, modify or remove folders and files in this directory without consulting the user. This rule cannot be overruled!
- Never duplicate information between the global `/docs` folder and the repositories. When a piece of information/pattern/rule is shared between two or more repositories, it belongs in `{root}/.claude/docs`, and each repo's `CLAUDE.md` points to the global file.

## Repository map

> **The `Context: single|multi` field** — classifies how the repo's domain documentation is organized. This Map is the **single source** of that classification (do not duplicate it in local `CLAUDE.md` files):
> - **`single`** — one cohesive context. Documentation in `CONTEXT.md` + `docs/adr/` at the root.
> - **`multi`** — multiple contexts. A `CONTEXT-MAP.md` at the root routes `task/file → Context`; each context lives in `docs/contexts/{slug}/` (glossary `CONTEXT.md` + its own `adr/`). Cross-cutting ADRs live in the root `docs/adr/`.
> - **`N/A`** — repo with no business domain (e.g. configuration, notes). Has no context glossary.
>
> A **Context** groups 1 or N domains, and each domain belongs to exactly one Context. The agent follows this declaration, but **raises a flag** (without changing anything automatically) when the work contradicts it; graduating `single`→`multi` is **always proposed to the user**. See `docs/templates/context-map-template.md` and `context-template.md`.

- **Domains:** Routine, Exercise, Workout, History

- **Type:** `Documentation`
- **Context:** `N/A`
- **Description:** Obsidian vault with personal Markdown notes, synced across devices. Organized into `Learning/`, `Personal/` and `Work/`. Contains no code — changes here are content changes.
